Làm Quen Với Amazon S3

Hiểu các khái niệm cốt lõi của S3 và tự tay tạo bucket, tải file, phân quyền truy cập — dành cho người mới bắt đầu, không cần kinh nghiệm trước.

1

S3 là gì?

▾

S3 (Simple Storage Service) là dịch vụ lưu trữ đối tượng (object storage) của AWS. Khác với EC2 (máy chủ tính toán) hay EBS (ổ đĩa gắn vào máy chủ), S3 lưu file (gọi là object) một cách độc lập, không cần máy chủ nào chạy — bạn chỉ trả tiền theo dung lượng lưu trữ và số lượt truy cập.

Ví dụ dễ hình dung: S3 giống như một kho lưu trữ khổng lồ chia thành các "tủ đồ" riêng biệt (bucket). Mỗi tủ đồ có tên riêng, duy nhất trên toàn thế giới. Bên trong mỗi tủ, bạn cất bao nhiêu món đồ (object) tùy thích — mỗi món có một "nhãn dán đường dẫn" (key) để tìm lại. Bạn quyết định ai được mở tủ, ai chỉ được xem một món cụ thể (permissions/policy).
✓
Không giống EC2: S3 không có khái niệm "instance đang chạy" — dữ liệu tồn tại độc lập, không cần server nào bật. Đây là lý do S3 thường được gọi là "serverless storage".

3

Storage Class: chọn hạng nào?

▾

Storage class ảnh hưởng trực tiếp đến chi phí lưu trữ và tốc độ truy xuất dữ liệu.

Storage ClassPhù hợp vớiĐặc điểm
S3 StandardDữ liệu truy cập thường xuyênChi phí lưu trữ cao hơn, truy xuất tức thì, không phí lấy dữ liệu
S3 Standard-IADữ liệu ít truy cập nhưng cần nhanh khi cầnLưu trữ rẻ hơn, có phí khi truy xuất (retrieval fee)
S3 Glacier Instant RetrievalLưu trữ dài hạn, hiếm khi truy cậpRất rẻ, truy xuất tức thì nhưng phí retrieval cao hơn IA
S3 Glacier Deep ArchiveLưu trữ lâu dài, gần như không truy cậpRẻ nhất, thời gian khôi phục có thể mất vài giờ
⚠
Lưu ý chi phí: S3 không tính phí cố định theo tháng như EC2 — bạn trả theo dung lượng lưu trữ, số request, và data transfer ra ngoài internet. Xóa các file thử nghiệm sau khi lab xong để tránh phí lưu trữ tích lũy.
4

Thực hành: Tạo bucket và quản lý object

▾

Mục tiêu: Tạo một S3 bucket, tải file lên, thử phân quyền public đọc, và dọn dẹp sau khi xong.

1

Tạo bucket mới

Console → S3 → Create bucket. Đặt tên duy nhất toàn cầu (vd: yen-lab-s3-demo-2026), chọn Region ap-southeast-1. Giữ nguyên "Block all public access" ở bước này.

2

Tải file lên bucket (Upload)

Vào bucket vừa tạo → Upload → chọn một file bất kỳ (vd: ảnh hoặc file text) → Upload. Đây chính là "object" đầu tiên của bạn.

3

Xem thuộc tính object

Click vào tên file vừa upload → xem tab Properties (storage class, kích thước, thời gian tạo) và tab Permissions.

4

Bật Versioning cho bucket

Vào tab Properties của bucket → Bucket Versioning → Enable. Sau đó thử upload đè lên cùng một file — vào tab Versions để thấy cả 2 phiên bản đều được giữ lại.

5

Thử cấp quyền đọc public (tùy chọn, cẩn trọng)

Tắt "Block all public access" ở cấp bucket → thêm Bucket Policy cho phép s3:GetObject từ "*" → thử mở URL object trực tiếp trên trình duyệt.

6

Dọn dẹp: xóa object và bucket

Xóa toàn bộ object (kể cả các version cũ nếu đã bật Versioning) → sau đó xóa bucket để tránh phát sinh phí lưu trữ về sau.

🔒
Best practice bảo mật: Trong môi trường thực tế, hầu như không nên mở public bucket. Thay vào đó, dùng CloudFront + Origin Access Control (OAC) hoặc Presigned URL để chia sẻ file có kiểm soát và có thời hạn.
5

Thực hiện bằng AWS CLI

▾

Toàn bộ quy trình trên cũng có thể thực hiện bằng CLI (region: ap-southeast-1):

# Tạo bucket
aws s3api create-bucket \
  --bucket yen-lab-s3-demo-2026 \
  --region ap-southeast-1 \
  --create-bucket-configuration LocationConstraint=ap-southeast-1

# Upload file lên bucket
aws s3 cp ./hello.txt s3://yen-lab-s3-demo-2026/hello.txt

# Liệt kê object trong bucket
aws s3 ls s3://yen-lab-s3-demo-2026/

# Bật Versioning
aws s3api put-bucket-versioning \
  --bucket yen-lab-s3-demo-2026 \
  --versioning-configuration Status=Enabled

# Xem các version của một object
aws s3api list-object-versions \
  --bucket yen-lab-s3-demo-2026 \
  --prefix hello.txt

# Xóa object rồi xóa bucket
aws s3 rm s3://yen-lab-s3-demo-2026/hello.txt
aws s3 rb s3://yen-lab-s3-demo-2026 --force
