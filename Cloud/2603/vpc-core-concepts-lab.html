Từ cơ bản đến nâng cao: xây dựng nền tảng networking cho mọi kiến trúc AWS

1️⃣ VPC & CIDR Block — Nền móng của mạng riêng

▼

VPC (Virtual Private Cloud) là một mạng riêng ảo, cô lập về mặt logic trong AWS, nơi bạn kiểm soát hoàn toàn dải IP, subnet, route table và cấu hình gateway.

🏢 VÍ VON
VPC giống như bạn thuê nguyên một khu đất để xây khu công nghiệp. Bạn tự quyết định chia lô đất (subnet), xây đường nội bộ (route table), đặt cổng ra vào (Internet Gateway), và ai được ra vào (Security Group). AWS chỉ cho bạn thuê đất — còn quy hoạch là việc của bạn.

CIDR Block là gì?

CIDR (Classless Inter-Domain Routing) định nghĩa dải địa chỉ IP mà VPC sở hữu, viết dưới dạng x.x.x.x/n. Số /n càng nhỏ, dải IP càng lớn.

CIDRSố IPDùng cho
/1665,536 IPVPC lớn, nhiều subnet (khuyến nghị)
/24256 IPSubnet phổ biến
/2816 IPSubnet rất nhỏ (VD: NAT, endpoint riêng)
⚠️
Lưu ý quan trọng: Mỗi subnet, AWS luôn giữ lại 5 địa chỉ IP không dùng được (network address, VPC router, DNS, future use, broadcast address). Một subnet /24 có 256 IP nhưng chỉ dùng được 251.
💡
Best practice: Chọn CIDR VPC đủ rộng ngay từ đầu (VD: 10.0.0.0/16) và tránh trùng với CIDR on-premise nếu sau này cần VPN/Direct Connect — trùng CIDR sẽ gây xung đột routing.

2️⃣ Subnet — Public vs Private

▼

Subnet là một phân vùng IP trong VPC, luôn nằm gọn trong một Availability Zone (AZ) duy nhất. Một VPC thường có nhiều subnet trải trên nhiều AZ để đạt tính sẵn sàng cao.

🏭 VÍ VON
Nếu VPC là khu đất, thì subnet là từng khu nhà xưởng được xây trên đó — mỗi khu nằm cố định trong một khu vực địa lý (AZ) và có cổng ra riêng.

Điều gì quyết định Public hay Private?

Không có thuộc tính "public/private" gắn cứng vào subnet. Nó hoàn toàn do route table quyết định:

  • Public subnet: route table có route trỏ 0.0.0.0/0 → Internet Gateway (IGW)
  • Private subnet: route table không có route thẳng ra IGW (có thể qua NAT Gateway để ra internet một chiều)
┌─────────────────────────── VPC (10.0.0.0/16) ───────────────────────────┐ │ │ │ ┌──────────── AZ-a ────────────┐ ┌──────────── AZ-b ────────────┐ │ │ │ Public Subnet 10.0.1.0/24 │ │ Public Subnet 10.0.2.0/24 │ │ │ │ (route → IGW) │ │ (route → IGW) │ │ │ │ [ ALB / Bastion / NAT GW ] │ │ [ ALB / Bastion ] │ │ │ └───────────────────────────────┘ └───────────────────────────────┘ │ │ │ │ ┌──────────── AZ-a ────────────┐ ┌──────────── AZ-b ────────────┐ │ │ │ Private Subnet 10.0.11.0/24 │ │ Private Subnet 10.0.12.0/24 │ │ │ │ (route → NAT GW) │ │ (route → NAT GW) │ │ │ │ [ EC2 App / ECS Tasks ] │ │ [ EC2 App / ECS Tasks ] │ │ │ └───────────────────────────────┘ └───────────────────────────────┘ │ │ │ │ ┌──────────── AZ-a ────────────┐ ┌──────────── AZ-b ────────────┐ │ │ │ DB Subnet 10.0.21.0/24 │ │ DB Subnet 10.0.22.0/24 │ │ │ │ (no route out) │ │ (no route out) │ │ │ │ [ RDS Multi-AZ ] │ │ [ RDS Multi-AZ standby ] │ │ │ └───────────────────────────────┘ └───────────────────────────────┘ │ └──────────────────────────────────────────────────────────────────────────┘
💡
Design pattern chuẩn 3 lớp: Public subnet (load balancer) → Private subnet (app server/ECS) → DB subnet (RDS, không có route ra ngoài). Đây chính là pattern bạn đã áp dụng ở lab RDS Multi-AZ.

3️⃣ Internet Gateway & NAT Gateway

▼

Internet Gateway (IGW)

Là cửa ngõ 2 chiều cho phép resource trong public subnet giao tiếp trực tiếp với internet. Mỗi VPC chỉ gắn được 1 IGW, và IGW không có giới hạn băng thông hay tính phí theo giờ.

NAT Gateway

Cho phép resource trong private subnet chủ động ra internet (VD: tải update, gọi API bên ngoài) nhưng internet không thể chủ động kết nối vào — đây là kết nối 1 chiều.

Tiêu chíNAT GatewayNAT Instance
Quản lýAWS managed, tự động HA trong AZTự quản lý (EC2)
Băng thôngĐến 100 Gbps, tự scaleGiới hạn theo instance type
Chi phíTheo giờ + theo GB xử lýChi phí EC2 instance
Security GroupKhông áp dụng đượcCó thể áp dụng SG
Khuyến nghị✅ ProductionChỉ dùng khi cần custom/tiết kiệm
💰
Chi phí ẩn: NAT Gateway tính phí theo giờ chạy (~0.045 USD/h ở nhiều region) cộng thêm phí theo mỗi GB dữ liệu đi qua. Với hệ thống nhiều AZ, mỗi AZ nên có 1 NAT Gateway riêng để tránh single point of failure — nhưng điều này nhân chi phí lên tương ứng.
💡
Tiết kiệm chi phí: Nếu chỉ cần private subnet gọi tới S3/DynamoDB, dùng VPC Gateway Endpoint (miễn phí) thay vì NAT Gateway để giảm chi phí data transfer đáng kể.

4️⃣ Route Table — "Bộ não" định tuyến

▼

Route Table chứa các quy tắc (route) xác định traffic từ subnet sẽ đi đâu. Mỗi subnet phải gắn với đúng 1 route table (nếu không gắn tường minh, nó dùng Main Route Table mặc định của VPC).

Ví dụ Route Table của Public Subnet 
Destination         Target
10.0.0.0/16         local            # traffic nội bộ VPC
0.0.0.0/0           igw-0abc1234     # mọi traffic khác ra Internet Gateway
Ví dụ Route Table của Private Subnet 
Destination         Target
10.0.0.0/16         local            # traffic nội bộ VPC
0.0.0.0/0           nat-0def5678     # ra ngoài qua NAT Gateway
🔒
Bẫy thường gặp: Quên gắn route table đúng cho subnet khiến nó rơi về Main Route Table mặc định — dẫn đến subnet "public" theo thiết kế nhưng thực chất không có đường ra IGW (hoặc ngược lại, private subnet vô tình có đường ra ngoài).

5️⃣ Security Group vs Network ACL

▼

Đây là 2 lớp firewall trong VPC, hoạt động ở tầng khác nhau và có bản chất khác nhau hoàn toàn.

Tiêu chíSecurity GroupNetwork ACL
Áp dụng choENI / InstanceSubnet (toàn bộ)
Trạng tháiStateful — traffic trả về tự động cho phépStateless — phải khai báo rule cho cả 2 chiều
RuleChỉ có AllowCó cả Allow và Deny
Thứ tự xử lýĐánh giá toàn bộ ruleXử lý theo số thứ tự rule tăng dần, dừng ở rule khớp đầu tiên
Số lượng/resourceNhiều SG gắn cho 1 ENI1 NACL cho 1 subnet
🚪 VÍ VON
Security Group giống bảo vệ đứng trước cửa từng căn phòng (instance) — nhớ mặt ai đã vào thì tự động cho ra mà không cần hỏi lại (stateful). NACL giống trạm kiểm soát ở cổng khu công nghiệp (subnet) — kiểm tra từng xe ra vào độc lập, xe vào rồi muốn ra vẫn phải qua kiểm tra riêng (stateless).
🔒
Best practice bảo mật: Dùng Security Group làm lớp chính (least privilege, chỉ allow cần thiết). NACL nên dùng cho các rule deny tường minh ở cấp subnet — VD: block hẳn 1 dải IP độc hại mà không cần touch từng SG.

6️⃣ VPC Peering & VPC Endpoints

▼

VPC Peering

Kết nối trực tiếp 1-1 giữa 2 VPC (cùng hoặc khác account/region), traffic đi qua mạng riêng của AWS, không qua internet.

⚠️
Giới hạn quan trọng: Peering không bắc cầu (non-transitive) — nếu VPC-A peer với VPC-B, và VPC-B peer với VPC-C, thì A không tự động thấy C. Với nhiều VPC cần giao tiếp, nên cân nhắc Transit Gateway thay vì peering hình sao/mesh phức tạp.

VPC Endpoints

Cho phép traffic từ VPC tới AWS service không cần đi qua internet/NAT Gateway.

LoạiDùng choChi phí
Gateway EndpointChỉ S3 và DynamoDBMiễn phí
Interface Endpoint (PrivateLink)Hầu hết service khác (EC2, SSM, ECR, Secrets Manager...)Tính phí theo giờ + GB
💡
Kết nối với lab ECS/ECR của bạn: Nếu ECS Fargate task trong private subnet cần pull image từ ECR mà không muốn tốn NAT Gateway, có thể dùng Interface Endpoint cho ecr.api, ecr.dkr và Gateway Endpoint cho S3 (vì image layer lưu ở S3).

7️⃣ Lab thực hành: Dựng VPC 2-tier bằng CLI

▼

Thực hành tạo 1 VPC với public + private subnet, IGW, NAT Gateway và route table hoàn chỉnh.

Tạo VPC

bash 
aws ec2 create-vpc \
  --cidr-block 10.0.0.0/16 \
  --region ap-southeast-1 \
  --tag-specifications 'ResourceType=vpc,Tags=[{Key=Name,Value=lab-vpc}]'

Tạo Public & Private Subnet

bash 
aws ec2 create-subnet --vpc-id vpc-xxxx \
  --cidr-block 10.0.1.0/24 \
  --availability-zone ap-southeast-1a \
  --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=public-1a}]'

aws ec2 create-subnet --vpc-id vpc-xxxx \
  --cidr-block 10.0.11.0/24 \
  --availability-zone ap-southeast-1a \
  --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=private-1a}]'

Tạo & gắn Internet Gateway

bash 
aws ec2 create-internet-gateway \
  --tag-specifications 'ResourceType=internet-gateway,Tags=[{Key=Name,Value=lab-igw}]'

aws ec2 attach-internet-gateway \
  --internet-gateway-id igw-xxxx \
  --vpc-id vpc-xxxx

Tạo Route Table cho Public Subnet

bash 
aws ec2 create-route-table --vpc-id vpc-xxxx \
  --tag-specifications 'ResourceType=route-table,Tags=[{Key=Name,Value=public-rt}]'

aws ec2 create-route --route-table-id rtb-xxxx \
  --destination-cidr-block 0.0.0.0/0 \
  --gateway-id igw-xxxx

aws ec2 associate-route-table --route-table-id rtb-xxxx \
  --subnet-id subnet-public-xxxx

Tạo NAT Gateway cho Private Subnet

bash 
# Cần Elastic IP trước
aws ec2 allocate-address --domain vpc

aws ec2 create-nat-gateway \
  --subnet-id subnet-public-xxxx \
  --allocation-id eipalloc-xxxx \
  --tag-specifications 'ResourceType=natgateway,Tags=[{Key=Name,Value=lab-nat}]'

# Route cho private subnet trỏ qua NAT
aws ec2 create-route --route-table-id rtb-private-xxxx \
  --destination-cidr-block 0.0.0.0/0 \
  --nat-gateway-id nat-xxxx
💰
Nhớ dọn dẹp sau lab: NAT Gateway và Elastic IP (khi chưa gắn) đều tính phí theo giờ. Xóa NAT Gateway trước, đợi vài phút rồi release Elastic IP để tránh phí phát sinh ngoài ý muốn.

8️⃣ Kiểm tra kiến thức

▼

1. Một subnet có thể trải trên nhiều Availability Zone không?

✅ Đúng: Subnet bị ràng buộc vào 1 AZ ngay khi tạo. Muốn HA đa AZ, bạn phải tạo nhiều subnet, mỗi cái ở 1 AZ khác nhau.

2. Điều gì quyết định một subnet là "public"?

✅ Đúng: Không có cờ "public/private" trong AWS — hoàn toàn do route table quyết định.

3. Khác biệt cốt lõi giữa Security Group và NACL là gì?

✅ Đúng: SG tự động cho phép traffic trả về (stateful). NACL phải khai báo rule riêng cho inbound và outbound (stateless), và là loại duy nhất hỗ trợ rule Deny.

4. VPC Peering giữa A-B và B-C có cho phép A giao tiếp trực tiếp với C không?

✅ Đúng: Phải tạo thêm peering A-C trực tiếp, hoặc dùng Transit Gateway nếu số lượng VPC nhiều.

5. Muốn private subnet gọi tới S3 mà không tốn phí NAT Gateway, nên dùng gì?

✅ Đúng: Gateway Endpoint hỗ trợ S3 và DynamoDB, hoàn toàn miễn phí và không cần NAT Gateway.
