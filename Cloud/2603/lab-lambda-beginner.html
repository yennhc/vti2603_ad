Làm Quen Với AWS Lambda

Hiểu các khái niệm cốt lõi của serverless computing và tự tay viết, triển khai hàm Lambda đầu tiên — dành cho người mới bắt đầu, không cần kinh nghiệm trước.

1

Lambda là gì?

▾

AWS Lambda là dịch vụ serverless compute — bạn chỉ viết code (gọi là function), tải lên AWS, và Lambda tự động chạy code đó khi có sự kiện kích hoạt (trigger). Bạn không cần quản lý máy chủ, không cần cài OS, không cần lo scaling — AWS lo tất cả phần hạ tầng.

Ví dụ dễ hình dung: Nếu EC2 giống như thuê hẳn một căn hộ (phải tự bật/tắt điện, dọn dẹp, bảo trì dù có ở hay không), thì Lambda giống như gọi taxi công nghệ — bạn chỉ trả tiền cho đúng chuyến đi (mỗi lần function chạy), không cần sở hữu xe, không lo bảo dưỡng. Khi không có ai gọi, bạn không trả đồng nào.
✓
Khác biệt lớn nhất với EC2: Lambda không "chạy liên tục". Nó chỉ "thức dậy" khi có sự kiện gọi đến, xử lý xong rồi "ngủ lại" — mô hình này gọi là event-driven.
2

Các khái niệm cốt lõi

▾
Khái niệmGiải thích
FunctionĐơn vị code bạn viết và triển khai lên Lambda — chứa logic xử lý.
HandlerHàm entry-point cụ thể mà Lambda gọi đầu tiên khi function được kích hoạt (vd: index.handler).
TriggerSự kiện kích hoạt function chạy — API Gateway, S3 upload, EventBridge (lịch), SQS, DynamoDB Stream...
RuntimeMôi trường ngôn ngữ để chạy code (Node.js, Python, Java, Go...).
Execution RoleIAM Role gán cho function, quyết định function được phép gọi những dịch vụ AWS nào.
Cold StartĐộ trễ khởi tạo môi trường khi function chạy lần đầu (hoặc sau thời gian dài không dùng).
Timeout / MemoryGiới hạn thời gian chạy tối đa (tối đa 15 phút) và bộ nhớ cấp phát (128MB–10GB), ảnh hưởng cả hiệu năng lẫn chi phí.
LayerGói thư viện/dependency dùng chung, có thể gắn vào nhiều function khác nhau.

Ghi nhớ nhanh: Trigger đánh thức → Handler xử lý → Execution Role quyết định function được làm gì.

3

Trigger phổ biến: khi nào Lambda chạy?

▾

Lambda hầu như luôn được gọi bởi một dịch vụ AWS khác, chứ hiếm khi tự chạy độc lập.

TriggerKích hoạt khi nàoVí dụ dùng thực tế
API GatewayCó HTTP request gọi đến endpointXây REST API serverless, backend cho web/app
S3 EventFile được upload/xóa trong bucketTự động resize ảnh khi upload
EventBridge (Scheduled)Theo lịch định kỳ (cron)Chạy báo cáo hàng ngày, dọn dẹp dữ liệu cũ
SQS / SNSCó message mới trong queue/topicXử lý hàng đợi tác vụ bất đồng bộ
DynamoDB StreamsDữ liệu trong bảng thay đổiĐồng bộ dữ liệu real-time sang hệ thống khác
⚠
Lưu ý chi phí: Lambda tính phí theo số lần gọi (invocation) và thời gian thực thi × bộ nhớ cấp phát. Free Tier cho 1 triệu request/tháng và 400,000 GB-giây compute miễn phí — đủ để thực hành thoải mái.
4

Thực hành: Tạo và test function đầu tiên

▾

Mục tiêu: Tạo một Lambda function bằng Python, test trực tiếp trên Console, sau đó gắn một API Gateway trigger đơn giản.

1

Tạo function mới

Console → Lambda → Create function → "Author from scratch". Đặt tên (vd: lab-hello-function), chọn Runtime Python 3.12, giữ nguyên execution role mặc định (tạo mới với quyền cơ bản).

2

Viết code xử lý đơn giản

Trong tab Code, thay nội dung file lambda_function.py:

import json

def lambda_handler(event, context):
    name = event.get('queryStringParameters', {}).get('name', 'AWS learner') if event.get('queryStringParameters') else 'AWS learner'
    return {
        'statusCode': 200,
        'body': json.dumps({'message': f'Xin chào, {name}! Function đã chạy thành công.'})
    }

Bấm Deploy để lưu thay đổi.

3

Test function ngay trên Console

Tab Test → tạo test event mới (dùng template rỗng {}) → bấm Test → xem kết quả trả về và log thực thi bên dưới.

4

Gắn trigger API Gateway

Tab Configuration → Triggers → Add trigger → chọn API Gateway → "Create a new API", loại HTTP API, security Open (chỉ để test, không dùng cho production).

5

Gọi function qua URL công khai

Sau khi trigger được tạo, copy API endpoint URL → mở trên trình duyệt hoặc thêm query string ?name=Yen để thấy response thay đổi theo tham số.

6

Xem log thực thi trên CloudWatch

Tab Monitor → View CloudWatch logs — mỗi lần function chạy đều tự động ghi log tại đây, hữu ích để debug.

7

Dọn dẹp

Xóa API Gateway trigger và xóa function sau khi thực hành xong để tránh phát sinh tài nguyên thừa (dù chi phí Lambda ở mức nhỏ này gần như bằng 0).

🔒
Best practice bảo mật: Luôn áp dụng nguyên tắc least privilege cho Execution Role — chỉ cấp đúng quyền function cần dùng (vd: chỉ s3:GetObject nếu chỉ cần đọc, không cấp full s3:*).
5

Thực hiện bằng AWS CLI

▾

Toàn bộ quy trình trên cũng có thể thực hiện bằng CLI (region: ap-southeast-1):

# Đóng gói code thành file zip
zip function.zip lambda_function.py

# Tạo function mới (cần execution-role ARN có sẵn)
aws lambda create-function \
  --function-name lab-hello-function \
  --runtime python3.12 \
  --role arn:aws:iam::<ACCOUNT_ID>:role/lambda-basic-execution \
  --handler lambda_function.lambda_handler \
  --zip-file fileb://function.zip \
  --region ap-southeast-1

# Gọi function trực tiếp để test
aws lambda invoke \
  --function-name lab-hello-function \
  --payload '{"queryStringParameters": {"name": "Yen"}}' \
  --cli-binary-format raw-in-base64-out \
  response.json
cat response.json

# Xem log gần nhất trên CloudWatch
aws logs tail /aws/lambda/lab-hello-function --follow

# Xóa function khi xong
aws lambda delete-function --function-name lab-hello-function
